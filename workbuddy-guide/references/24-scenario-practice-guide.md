## 场景 A：做一个「能发布」的个人网站/作品集

**痛点**：不懂编程、不懂设计，但想要一个能点击、能交互、能发布的个人网站（作品集/产品页/简历/相册）。

**完整动线（6 步）**：

```
1. 切「设计创意」模式 → 对话框上方点「网站设计」
2. 先聊灵感，别急着甩需求：
   说清 ①做什么内容 ②给谁看 ③目的是什么
   → WorkBuddy 反推需要哪些板块（Hero首页/项目展示/个人介绍/联系方式）
3. 立骨架（一次性交代清楚，别想到哪说到哪）：
   身份 + 风格基调 + 板块清单 + 「适合 PC 端展示」
4. 截图给参考：不会写设计术语就截图——截要改的部分 + 截参考网页，文字描述效果
5. 加动效/视频：截图+参考图+文字，说清「什么时候动、怎么动」；
   视频拖进对话框，说清插哪、怎么播（播放按钮/时长/滚动自动播）
6. 预览走查 → 一键发布：右上角「转发」→「复制链接」→「发布为网站」（workbuddy.link）
   后续更新：资料库进编辑模式改 → 分享 →「同步」
```

**提示词骨架模板**：
```
我的身份是 XX 设计师，要做作品集，整体清新、绿色主调、高级克制。页面需包含：
1 全屏首页 Hero（视频背景+大标题+导航+联系按钮）
2 个人经历模块（头像+介绍+联系方式+工作经历）
3 项目模块（大卡片展示作品图）
4 个人优势模块（卡片展示能力）
5 底部联系方式模块（整屏收尾页）
页面需适合 PC 端展示（后续要加图片/视频/动效）。
```

**提示**：对长期访问稳定性/加载速度有更高要求，可把代码同步 GitHub，用 GitHub Pages 独立部署作备选。

## 场景 B：D2C 设计稿转代码（进阶 · 设计师+开发协作）

**痛点**：传统交付链路（出稿→评审→开发→走查→改→再走查）动辄 2-3 天，需求一变全链重来。

**核心**：通过 **Ardot MCP 连接 WorkBuddy**，AI 直接从设计稿生成可运行页面代码。实测提效 ≈72%（2-3天→5-7小时），需求调整后再交付 ≈83%（3小时→0.5小时）。

**前提·需求分类**：
| 需求类型 | 要不要出设计稿 | 怎么做 |
|---------|--------------|--------|
| 标准化页面/模块（表格/卡片/常规表单） | 完全跳过 | 需求描述+规范文件，直接让 AI 生成 |
| 非标准化/高定制/复杂业务逻辑 | 只出关键界面 | 关键页设计 → AI 还原 → 补交互细节 |

**关键·规范先行（三个 Skill 沉淀）**：AI 生成代码好不好，取决于它读到什么规范。
- ①设计规范 Skill：喂典型页面/规范，沉淀色彩/组件/布局/交互规范
- ②需求转设计稿 Skill：读懂需求后调用布局模板、填充业务组件
- ③设计稿转代码 Skill：用组件映射表约束代码实现

**转码 5 步**：搭页面框架（设计稿链接+整页截图）→ 还原模块（明确排列关系）→ 抠细节（给具体值，如颜色 #FFE492）→ 人工走查兜底（防"连带破坏"）→ 补新场景规范（沉淀回 Skill 形成闭环）。

> 顺序铁律：**先框架后细节**，反了会浪费大量时间。交付前必须系统走查，拦截 AI 的小意外。

## 场景 C：IMA + WorkBuddy 定时备课工作流（教师场景）

**痛点**：资料散在各处、备课赶进度、调课临时调整打乱计划。

**完整动线（3 步）**：
```
1. ima 建学期知识库：往期教案课件/本学期教材/教学经验/课程表进度，分门别类
2. 开学前跑一版学期教案：
   「@本学期备课知识库，综合参考往期教案+教材+教学重点+课程表进度，生成本学期教案」
   核对无误存回知识库，作为每日定时任务的基础依据
3. 每日定时跑任务：
   左侧边栏「更多 → ima知识库」授权 → 新建定时任务：
   「每天17:00 调用本学期备课知识库，根据课程表/进度/学期教案确认次日课程，
    生成教案(目标/重难点/活动/练习)+配套PPT，先发我确认，确认后发到指定邮箱」
```

**闭环**：确认教案后发送邮箱，同时回存 ima 知识库，为后续备课持续积累。
