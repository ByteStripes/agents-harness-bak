# VMProtect 程序恢复

产出可复现的恢复文件及报告。将“内容已解压”“能够运行”“所有保护已移除”分别证明；自动工具成功退出仅代表其中一个阶段。用户已有授权和文件访问边界继续有效，不重复询问已明确的事项。文件路径、工具目录、版本与配置从当前任务获取，不套用案例地址。

## 开始与工具选择

1. 保留原文件，记录 SHA-256、PE 位数、入口、ImageBase、节、数据目录、TLS、导入和异常表。建立任务内的 tools、analysis、intermediate、output 目录。禁止覆盖输入。
2. 优先发现用户提供的工具与快捷方式目标。ExeInfoPE 可拖入样本识别；无 GUI 时可使用 DIE/diec、PE 解析。签名 Unknown 不否定保护存在，也不证明具体版本。区分用户提供版本与工具识别结论。
3. 先识别 native PE、托管程序集、DLL/驱动；本流程默认原生用户态 PE。托管、驱动、虚拟化函数需要调整路线，不能当作普通 EXE 直接运行。
   对 I386/PE32，先阅读 [x86 专用流程](references/x86-workflow.md)，使用 `--32bit` 及匹配的 catalog。不要复用 x64 地址、指针宽度、入口模式或调试上下文假设。
4. 核对保护选项：打包、导入/资源/字符串保护、虚拟化、变异、反调试、反虚拟机。即使未选择函数虚拟化，也不假定无 SDK 或自动生成的保护跳板。
5. 缺少工具时，在当前授权范围内查询官方文档/源仓库并下载到任务目录；记录来源、版本/提交及哈希。不要上传样本到在线脱壳服务，除非用户明确要求。不要为此修改系统安全配置。

静态检查可使用 `scripts/pe_inventory.py`（依赖 pefile），具体调用见脚本 `--help`。只读取输入，结果写入显式指定目录。

## 恢复路线

优先使用与架构、壳版本匹配的模拟解包和导入恢复方案；阅读 [references/workflow.md](references/workflow.md) 获取工具命令、入口误判、重定位和测试细节。模拟不支持样本时再转向调试器捕获 OEP、进程转储及 Scylla 导入重建，保留每步中间产物。

- 模拟中观察恢复页面、读写范围、导入解析、API/系统调用事件和当前地址。长时间运行时以状态变化判断进展，不因日志稀疏而终止，也不无依据地反复重跑。
- 首次执行到恢复节可能只是壳或 SDK 跳板。结合反汇编、调用图、栈与运行验证确认应用入口；EXE 的 CRT 启动、TLS 回调、DLL 的 DllMain 不能互换。
- 将转储中的模拟 API 地址、堆指针、句柄及运行后状态视为不可持久化状态。重建 IAT，并修复直接调用、跳转、指针槽和包装调用；区分调用点修复数与唯一导入数。
- 新增导入必须有来源证据；模拟地址的数值匹配不等于函数指针。交付前及出现跨系统 Entry Point Not Found 时阅读 [导入来源审计](references/import-provenance.md)，重点复核 final_scan_only 额外导入，不能仅凭在当前 Windows 上可运行认定正确。
- 检查文件布局、节权限、异常/unwind 表、TLS、Load Config、资源、重定位、目录边界和初始化状态。**不得默认清空 Load Config/TLS 或禁用 ASLR。** 只有证据支持且测试覆盖时才做针对性调整，并说明功能损失。
- 字符串分为压缩恢复、编码导入名、运行时解密三类。扫描能读到字符串不代表所有字符串已解密；记录解密入口、引用、编码与长度，按实际需要恢复字符串及调用语义。
- 反调试/反虚拟机处理要定位到具体检查或证明启动时绕过相应初始化路径。不把导入中出现 IsDebuggerPresent、VirtualAlloc 或 RtlVirtualUnwind 等名称当作需要删除的证据。不改动业务激活校验来伪装恢复成功。
- 删除壳段前分析直接/间接代码引用、指针、异常处理器、TLS、资源及数据目录。仅改节名或抹掉壳签名不是脱壳；无法证明可删时保留并披露残留。

## 验证与交付门槛

保持原版与候选版的输入、参数、工作目录策略、标准输入 EOF、超时及运行环境一致。先选择不会产生无关外部副作用的测试路径。用户只授权静态分析时不运行样本。

普通命令行程序可用 `scripts/compare_runs.py` 对比，必须显式传 `--execute`、两份文件、输入字节文件和结果目录。它只适用于有界标准输入/输出的单进程测试，不涵盖交互 UI、子进程生命周期或真实调试验证。

至少分别记录：

- PE 结构能解析、文件能装载、是否超时、退出码、标准输出与错误；超时后强制终止不算正常退出。
- 已验证输入及分支；有效输入缺失时保留未测试结论。
- 实际附加调试器后的行为，而非仅在模拟器中设置 BeingDebugged=0。初始系统断点与访问异常分开记录。
- 如要声称移除反虚拟机限制，须提供对应虚拟化环境实测或对具体检查的充分代码证据；普通宿主机运行不够。
- ASLR、首选基址限制和保留的保护依赖。与沙箱强制重定位有关的失败先查实际装载地址，不能只凭 WinError 文案认定原因。

最终文件每次修改后重跑相关验证；记录交付版哈希，保留可重复构建脚本和补丁前后证据。使用 [references/report-outline.md](references/report-outline.md) 写报告。状态只能按证据写成“分析中间件”“已验证路径的可运行恢复版”或有充分证据的“完整去保护版”。未达到可运行门槛时继续定位；遇到工具不支持/缺少必要输入且无可行进展时交付诊断，不用换扩展名掩盖失败。
