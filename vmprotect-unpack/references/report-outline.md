# 逆向报告内容

按证据填写，不把未完成事项写成已完成：

1. **结论和交付等级**：恢复文件位置，可运行范围，是否保留保护代码及固定基址限制。
2. **样本标识**：输入/输出哈希和大小，架构，ImageBase，入口，节与目录；保护版本的证据来源。
3. **方法与复现**：工具来源/版本/提交/哈希、依赖、命令、日志位置、所需权限与执行环境。
4. **修复细节**：解压范围，候选入口验证，IAT/API 引用修复，TLS、异常、重定位、Load Config、资源和字符串的处理证据。每个修改记录理由、RVA/文件偏移、前后值。
5. **反调试/反虚拟机**：明确已移除的具体检查、绕过的启动路径、残余依赖及实际测试环境；没有测试就写未测试。
6. **测试矩阵**：原版与候选版输入、参数、EOF、工作目录、环境、自然退出/超时、输出及错误；标明缺少有效输入等覆盖限制。
7. **未解决内容**：保留调用、SDK/字符串路径、ASLR、无法证明的功能等，并写明下一步所需证据。
8. **交付清单**：最终 EXE/DLL、报告、补丁/重建脚本、导入清单与关键日志。中间文件单独命名；最终哈希与被测试文件一致。

不要声称：扫描器不再报壳就完全脱壳、某个错误输入可运行就全部等价、无虚拟化选项就不存在保护跳板、模拟器通过就真实虚拟机通过。
